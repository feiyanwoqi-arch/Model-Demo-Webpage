# 交互式物理模型核心构建标准 v1.1

版本日期：2026-08-04

本标准由单层薄膜干涉旗舰从 v0.8 到 v0.12 的多轮升级中提炼，随后应用于反射前三个基础模型。v1.1 根据 R1 的真实浏览器视觉返工进一步补充：**代码、断言和截图文件都只是证据源，浏览器中的真实呈现与真实任务完成情况才是最终验收对象。**

## 一、模型的最终定位

一个合格的交互模型不是“可拖动动画”，也不是“把教材图搬到网页”。它应当是一个可以连续执行以下闭环的虚拟物理工作台：

```text
明确研究对象
→ 直接操控物理状态
→ 同时观察互补表示
→ 建立因果归因
→ 读取可观测量
→ 检查公式、近似和边界
```

项目验收不再以页面板块数量、动画数量或视觉华丽程度为主要标准，而以用户能否完成上述闭环为准。

## 二、十二个核心构建点

### 1. 先定义不可隐藏的“物理本体”

每个模型必须先回答：用户真正操控的对象是什么？

- 反射定律：入射方向、入射点和局部法线；
- 平面镜：物体、镜面、眼睛与真实反射光；
- 球面镜：物体、镜面、焦点、曲率中心与主光线；
- 薄膜干涉：三层介质、入射光线、膜厚和公共状态。

主实验台只能保留完成直接操作和即时判断所必需的对象。它必须始终可见，不能被侧栏或后续解释替代。

### 2. 单一状态源

几何图、装置图、曲线、相量、公式、数值和验证结果必须读取同一份状态对象。

禁止：

- 主图更新而曲线仍使用旧参数；
- 为了画图方便给不同板块维护各自的“近似状态”；
- 控件数值和直接拖动后的几何位置不一致。

### 3. 直接操作优先

能够对应物理对象的参数，应优先允许直接拖动对象本身；滑块作为精细调节和无障碍替代路径。

直接操作必须满足：

- 拖动方向和物理变化方向一致；
- 可见控制点、命中区和实际物理对象位置一致；
- 高分屏、浏览器缩放和响应式重排下命中坐标不漂移；
- 拖动时所有已选模块在同一状态更新；
- 触屏、鼠标和键盘路径均可使用；
- 自动验收必须真实发送指针事件，并确认状态数值确实变化，不能只检查监听器存在。

### 4. 多重表征必须有明确分工

页面不是把多张图并排陈列。每一个模块必须声明：

```text
目的：它要回答什么问题？
作用：它在因果链中承担什么职责？
操作：用户怎样验证它？
输入：读取哪些统一状态？
输出：产生什么可观察结果？
边界：在哪些条件下失效？
```

写不出这些字段的板块不得加入。

### 5. “状态同步”必须升级为“观察同步”

后台同时更新没有意义。用户操作主对象时，当前选择的互补视图必须同时处于视野内。

因此采用：

```text
主实验台常驻
＋ 可选择的同步分析区
＋ 按需出现的参数/模块抽屉
```

任务级标准不是“分析区容器足够宽”，而是“主实验台和所选模块在真实视口内同时可见、可读并能进行视觉对应”。

### 6. 建立可读性预算

同时显示多少模块，不由功能数量决定，而由视口、文字尺寸和图形最小可读面积决定。

- 薄膜旗舰允许 1–4 个模块，但两个模块时必须进入三视图专用布局；
- 反射基础模型每个分析图需要较大的几何可读面积，因此同屏预算固定为两个分析模块；
- 超出预算的内容仍可选择，但必须先关闭旧模块或使用放大模式。

“能塞进去”不等于“能读懂”。Canvas 的 DOM 外框完整可见，也不等于内部坐标轴、标签、图例和曲线可读。

### 7. 显示策略按任务性质决定

```text
直接操控对象                    → 常驻
用户主动选择的同步结果          → 选择后常驻
当前连续操作中的核心实时量      → 常驻紧凑显示
间歇性配置、筛选和模块选择      → 边缘轨道/可关闭抽屉
需要稳定阅读的解释              → 点击式展开
阻断式独立任务                  → 谨慎使用模态流程
```

侧栏不能按“左边还是右边”机械决定。悬停唤出必须同时提供点击、固定、关闭和触屏路径。

### 8. 必须连接现实装置与可观测量

每个模型至少回答两件事：

1. 现实中用什么光源、样品、屏幕、探测器或观察者建立实验？
2. 仪器真正测到的是方向、强度、位置、清晰度还是相位？

只有几何光路而没有测量链，仍然只是示意图。若观察者或探测器是核心变量，其接收量必须进入主实验台的常驻实时量，而不能只藏在参数抽屉或次级图中。

### 9. 公式必须回指物理对象

公式不是结尾装饰。推导链应说明：

```text
局部物理规律
→ 几何关系或边界条件
→ 数学表达
→ 可测结果
```

公式使用 MathJax/LaTeX，并明确符号、正负号、参考方向和适用近似。

### 10. 模型边界必须进入运行状态

边界不能只写在页面底部。参数逼近失效区域时，页面必须主动给出警告或验证项。

典型边界包括：

- 几何光学与波长尺度；
- 近轴近似；
- 无吸收、完全相干或平行界面；
- 教学用统计分布与真实 BRDF/散射理论的区别；
- 虚像、实像和屏幕接收的判据。

### 11. 图形必须按设备像素比重绘并保持几何比例

所有 Canvas 必须使用：

```text
内部像素 = CSS 显示尺寸 × devicePixelRatio
```

窗口、栏宽和浏览器缩放变化后重新建立 backing store，并保持逻辑坐标与拖动坐标一致。不得把低分辨率位图直接放大。

此外必须保证：

- CSS 重排不能改变 Canvas 的设计宽高比；
- 不得为了填满卡片而单向拉伸图形；
- 坐标轴、圆、角度、法线和光线方向不能因响应式布局发生视觉失真；
- 自动验收必须记录 Canvas 的实际显示宽高比，并与设计比例比较。

### 12. 验收必须模拟用户任务，并以真实呈现为最终事实

自动测试分为四层：

1. **语法与结构**：脚本加载顺序、注册字段、语义化控件；
2. **物理不变量**：守恒、极限、方程残差和判据；
3. **交互行为**：真实拖动、参数同步、模块挂载、抽屉操作；
4. **任务级视觉**：在目标视口中执行完整任务，并检查真实画面。

验收采用以下证据链：

```text
启动真实浏览器
→ 进入指定模型和指定视口
→ 执行完整学习任务
→ 生成关键状态截图与几何指标
→ 逐张查看真实画面
→ 记录视觉缺陷
→ 修改代码
→ 从头重跑同一任务
```

必须遵守以下规则：

- **真实渲染是最终事实源。** 代码意图、DOM 结构和测试通过不能覆盖浏览器中实际出现的裁切、重叠、失真或层级混乱。
- **截图生成成功不等于验收成功。** 截图必须由人或具备视觉能力的验收者逐张查看；未查看的截图不能作为完成证据。
- **几何断言和视觉查看互不替代。** 可见比例能发现出视口问题，但不能发现 Canvas 内部标签贴边、文字过小、圆被拉成椭圆、空白分配失衡等问题。
- **必须覆盖边界状态。** 至少包括默认态、拖动后状态、参数极端态、抽屉开启态、模块切换态和项目声明支持的最窄/最矮视口。
- **视觉缺陷属于测试失败。** 文本或图形裁切、标签碰撞、比例失真、关键对象不突出、控件遮挡、空白严重失衡、交互反馈不清晰，均不得以“功能正常”判定通过。
- **失败必须留下证据。** 验收脚本即使中途失败，也应尽可能保存已生成截图、失败步骤、浏览器错误与指标，避免只得到一个无上下文的红灯。
- **完成声明必须可复核。** 至少列出测试视口、执行任务、发现并修复的问题、最终截图清单和仍未覆盖的边界。

## 四、反射前三个模型的具体定位

### R1 反射定律与表面粗糙度

核心对象：入射方向、局部法线和观察方向。

必须同时区分：

- 单个微面元的严格方向镜像；
- 多个局部法线产生的宏观角分布；
- 观察者是否位于收到反射光的方向；
- “局部法线离散度示意参数”和真实波长级粗糙度/BRDF 的区别。

R1 的默认主视图必须同时显出：入射角、反射角、局部法线、观察方向、接受角和相对接收信号。观察者不能只是装饰点。

### R2 平面镜虚像

核心对象：物体、镜面、眼睛、真实反射光和反向延长线。

必须同时区分：

- 眼睛/相机能记录虚像；
- 镜后没有真实会聚光；
- 物像关于镜面对称；
- 有限镜面能否截获顶部、底部通向眼睛的必要光线。

### R3 球面镜成像

核心对象：物体、球面镜、焦点、曲率中心、主光线和屏幕。

必须同时区分：

- 近轴主光线与精确球面反射；
- 镜方程给出的近轴像点与实际有限口径焦散；
- 实像可在屏幕接收，虚像不能；
- 物距跨越 F、2F 时像的性质连续变化。

## 六、维护规则

1. 新页面先完成模型合同，再写 UI；
2. 主实验台不允许被装饰性内容挤压；
3. 新增模块必须先通过同屏可读性预算；
4. 新增近似必须同时新增边界与验证；
5. 修改拖动映射后必须运行真实指针验收，并验证状态值变化；
6. 修改布局后必须在用户实际报告过的视口尺寸复现任务；
7. 修改 Canvas 布局后必须检查内部图形宽高比、文字安全边距和标签碰撞；
8. 每张必需验收截图都必须被实际查看，并在报告中标注检查结果；
9. 未完成“发现问题—修复—完整重跑”的闭环，不得宣告完成；
10. GitHub 是唯一主代码源，代码、标准、测试和验证报告必须同轮更新。
