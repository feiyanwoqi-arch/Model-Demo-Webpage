# v0.9.1 模型页宽屏布局与可读性修复

版本日期：2026-08-04

## 问题来源

用户在 1764 px 宽的实际截图中发现：模型主体只占屏幕中部约六成，左右存在大面积空白，导致目录、参数、板块说明和图中标签显得过小。同时，顶部“实验状态与时间”控制条使用半透明 sticky 图层，滚动时后续卡片从其背后穿过，形成不自然的叠层效果。

根因是：

1. `.app` 使用固定 `max-width:1540px`；浏览器降低缩放比例后，CSS 视口变宽，但固定最大宽度不会同步占满物理屏幕；
2. 新增左目录和右参数栏后，固定总宽度进一步压缩中央主模型；
3. 多处辅助文字仍使用 9–11 px 的早期原型字号；
4. `.tf-command` 使用 `position:sticky`、高 z-index、半透明背景和 backdrop blur，造成内容在其下方滚动可见。

## 修复策略

### 1. 模型页全宽，主页保持编辑宽度

```css
.app { max-width:none; width:100%; }
#view:not(.mp-mounted) { max-width:1540px; margin-inline:auto; }
#view.mp-mounted { width:100%; max-width:none; }
```

因此：

- 主页和分类页仍保持适合阅读的最大宽度；
- 进入具体模型后可使用接近全部视口宽度；
- 不再因浏览器缩放而只占屏幕中间一块。

### 2. 三栏重新分配

宽屏模型页采用：

```text
左侧项目栏：250–292 px
中间实验区：剩余全部空间
右侧参数栏：370–430 px
```

超宽屏进一步增加到 300 px 左栏和 440 px 参数栏。小于 1320 px 后自动取消左右三栏，避免小屏拥挤。

### 3. 字号分层放大

重点增大：

- 项目栏标题、条目和副标题；
- 每节“目的—作用—建议操作”；
- 右侧参数名称、数值、状态和边界说明；
- 卡片标题、副标题、图注、画布脚注；
- 盲样报告、验证项和公式对象按钮。

不采用单纯全局放大，而是按信息层级分别调整，防止按钮和图形失衡。

### 4. 取消顶部悬浮叠层

顶部控制条改为普通文档流：

```css
.tf-command {
  position: static;
  background: #fff;
  backdrop-filter: none;
}
```

这样它会随页面正常滚走，后续板块不会从其背后经过。左侧项目栏仍然 sticky，承担长页面定位功能，因此不会损失导航能力。

### 5. 保持画布比例

图形会通过主内容列变宽而自然放大，不使用强制 `min-height` 拉伸 Canvas，避免改变内在宽高比和造成光路几何失真。

## 适用范围

本次样式主要作用于带 `.mp-mounted` 的模型页面。主页和分类页只获得更合理的外层响应式容器，不会无限横向拉伸正文卡片。

## 自动检查

`tests/model-page-guide-v09.test.js` 新增检查：

- v0.9.1 样式必须在基础项目栏样式之后加载；
- 模型容器不再锁死固定最大宽度；
- 主页与分类页仍保留 1540 px 阅读宽度；
- 左项目栏和右参数栏使用扩大后的响应式尺寸；
- 顶部控制条必须是 `position:static`；
- 取消 backdrop blur；
- 目的文字和目录文字已放大；
- 不允许用 Canvas 强制最小高度破坏比例。

## 人工验收重点

自动测试不能替代目标浏览器视觉检查。人工验收应关注：

1. 当前浏览器缩放比例下左右空白是否明显减少；
2. 14 px 目录正文和 13 px 板块说明是否达到实际可读性；
3. 顶部控制条滚出视口后是否完全消失，不再覆盖后续内容；
4. 左目录和右参数栏的 sticky 行为是否稳定；
5. 主画布变宽后，文字、角度标签和拖动热区是否仍与几何对象一致；
6. 1320 px 和 760 px 两个响应式断点是否自然。
