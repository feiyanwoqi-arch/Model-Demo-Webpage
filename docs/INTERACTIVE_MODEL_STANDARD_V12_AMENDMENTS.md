# 交互式物理模型核心标准 v1.2 增补

版本日期：2026-08-05

本增补由 R1 的真实运行、人工截图复验、PR 合并遗漏与 GitHub Pages 上线复查中提炼。它补充并收紧 `INTERACTIVE_MODEL_CONSTRUCTION_STANDARD_V1.md` v1.1；冲突时以本增补为准，待 R2 完成后合并回主标准正文。

## 一、完成状态必须分层

任何一次模型升级都必须明确区分以下状态：

```text
代码完成
→ 分支测试通过
→ 人工视觉复验通过
→ PR 可审阅
→ 合并进 main
→ 发布系统完成部署
→ 真实线上地址复验通过
```

这些状态不得互相替代。尤其禁止把“PR 已通过验收”表述为“网站已经更新”。

## 二、增加第十三个核心点：发布链也是产品的一部分

产品真实状态不是开发分支，而是用户实际访问到的页面。因此完成声明必须同时回答：

1. 代码当前位于哪个分支和提交；
2. 是否已合并到发布分支；
3. 发布机制读取哪个分支、目录或构建产物；
4. 发布是否完成；
5. 线上页面是否加载了本轮新增资源；
6. 强制刷新或无缓存访问后，真实画面是否与终验截图一致。

若第 2–6 项未完成，只能称为“开发完成”或“待发布”，不能称为“上线完成”。

## 三、测试工具必须接受反向校验

自动验收脚本不是绝对真理。测试失败时必须同时审查：

- 测试坐标是否与模型逻辑坐标一致；
- 浏览器滚动位置、缩放和 Canvas 映射是否正确；
- 选择器是否命中真实目标；
- 期望值是否符合当前物理状态；
- 测试是否把产品缺陷和测试脚本缺陷混为一谈。

至少设置一个可人工推导的基准动作，用来校验测试工具本身。例如已知控制点从 A 拖到 B 后，数值应落在明确区间，而不是只断言“发生变化”。

## 四、用户实拍画面具有最高纠偏权

实验室截图和几何指标通过后，用户实际浏览器截图仍可以推翻完成结论。因为真实环境还包含：

- 浏览器缩放；
- 页面缓存；
- 系统字体与文字渲染；
- 实际窗口大小而非名义屏幕分辨率；
- 发布延迟或旧资源缓存；
- 用户真实滚动位置和操作路径。

收到用户截图后，应先判断其加载的是哪一版本，再判断问题属于发布、缓存、响应式布局还是模型本身。不得先假定用户操作错误。

## 五、视觉验收新增“空白效率”指标

除了裁切与溢出，还必须检查：

- 主任务区域占视口的有效宽度比例；
- 左右空白是否来自合理阅读边距，还是旧版 `max-width` 限制；
- Canvas 内部物理内容是否集中在小区域，而大量画布没有信息；
- 同屏模块是否真正利用了宽屏，而不是把旧版窄布局居中展示。

对于桌面实验工作台，目标不是机械铺满，而是主任务区域通常应占可用视口宽度的约 88%–96%，同时保留边缘控件安全区。偏离该范围时必须人工解释。

## 六、资源加载必须可验证

新增 CSS/JS 后，终验必须检查：

- 资源已经写入发布入口；
- 加载顺序正确；
- `main` 中入口文件确实包含新资源；
- 线上 HTML 请求到的也是新入口；
- 旧资源不会在后加载时覆盖新修复；
- 页面切换到其他模型后，模型专用样式和运行时类能够清理。

## 七、R2 执行时采用的最新版闭环

```text
更新核心标准
→ 建立 R2 基线任务和截图
→ 人工查看当前真实呈现
→ 建立 R2 物理与视觉问题清单
→ 修改主实验台和分析模块
→ 多视口真实指针验收
→ 人工逐图复验
→ 合并 main
→ 检查发布分支入口
→ 真实线上地址无缓存复验
```

R2 未完成最后三步时，不得对用户宣告“网页已更新”。
