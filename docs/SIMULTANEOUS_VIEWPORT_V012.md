# v0.12 同屏因果闭环与任务级视觉验收

日期：2026-08-04

## 1. 失败现象

v0.11 已经让主实验台和已选分析模块共享状态，但当用户同时选择两个分析模块时，右侧模块仍按纵向完整卡片依次堆叠。结果是：

- 主实验台可见；
- 第一个分析模块可见；
- 第二个分析模块必须继续滚动才能看全；
- 用户拖动主光线时，无法在同一个视觉瞬间完成三者比较。

这违反了同步工作台的核心目的。状态同步只是必要条件，**同屏可见才让同步产生分析价值**。

## 2. 为什么旧自验收没有发现

旧 Playwright 审计测量了：

- 顶部标题高度；
- 主实验列宽度；
- 分析列宽度；
- 左右抽屉是否默认收起；
- 抽屉打开后的宽度和文字方向。

但它犯了三个方法论错误：

1. 把分析列当成一个整体，只测父容器，没有测内部每个已选模块；
2. 截图虽包含被截断的第二模块，但没有把“截图中是否同时看全”转化为数值断言；
3. 验收场景使用的是一般布局状态，而不是用户真正执行的任务：选择两个模块、收起侧栏、滚动到主操作区、连续拖动并比较三块视图。

因此这是**验收指标与用户任务错位**，不是简单漏看一张截图。

## 3. 调研后的设计原则

### 3.1 Split view 的价值是同时呈现互相关联的窗格

Apple 的 Split Views 指南将主画布、导航和检查器视为可同时呈现的相邻窗格，并要求为每个窗格设置合理的最小/最大尺寸；当空间不足时，可以隐藏辅助窗格，但不能让核心编辑或观察区域失去可用尺寸。

### 3.2 侧栏和辅助面板不能挤占主任务

Apple Sidebars 指南指出侧栏会消耗大量水平和垂直空间；空间有限时应采用更紧凑的控制。v0.11 已将模块和参数改为边缘抽屉，v0.12 进一步要求抽屉收起后释放出的空间必须真正转化成同步观察能力。

### 3.3 响应式布局必须保证内容和功能不丢失

WCAG Reflow 与 Resize Text 要求界面在不同窗口宽度和缩放条件下不丢失信息或功能。对于需要二维布局的交互实验，可以保留多窗格，但必须明确哪些窗格必须同屏，并为它们提供适当的重排或紧凑视图。

## 4. 最终形式：主实验台 + 两个全宽紧凑分析窗

当选择恰好两个分析模块时，进入 `triple` 模式：

```text
主实验台（左） | 分析模块 A（右上）
                 | 分析模块 B（右下）
```

右侧模块不改成两个狭窄缩略图。它们继续占据完整分析列宽，以保证 Canvas 中的线条、标签和数值仍可读。

为了让两张全宽图在一个视口内叠放，采用“语义裁剪”，只移除重复或低价值部分：

- Canvas 内部重复标题区；
- 大块无信息边缘留白；
- 已由外部卡片标题表达的说明；
- 底部重复图注。

不允许通过任意非等比压扁图形来换取高度。

每种模块注册自己的紧凑观察窗口：

- 实验装置：保留光源—准直—样品—探测器的完整链路；
- 界面相位：保留两个界面振幅和净反射相位差；
- 多束相量：保留相量链和精确总和；
- 光谱：保留主坐标区、工作波长和综合色；
- 相图：保留完整参数平面及当前位置；
- 测量与验证：保留核心图形，报告文字按需查看。

## 5. 新任务级验收标准

### 5.1 固定场景

自动浏览器必须执行：

1. 打开薄膜旗舰；
2. 打开左侧模块抽屉；
3. 选择“真实实验装置”和“界面反射相位”；
4. 收起抽屉；
5. 定位到主时间控制与主实验台；
6. 同时测量主实验卡和两个分析卡；
7. 截取当前视口。

### 5.2 同屏断言

在 2560×1440、1920×1080 和用户反馈对应的 1735×865 下：

- 三张卡片可见面积比例均不得低于 96%；
- 两个分析模块必须在同一个可读列中纵向排列且不得重叠；
- 每个分析 Canvas 窗口宽度不得低于 600 px；
- 装置窗口高度不得低于 220 px；
- 相位窗口高度不得低于 280 px；
- 页面不得产生横向溢出；
- 左右边缘抽屉仍应默认收起；
- Canvas 在裁剪窗口建立后必须重新进行高 DPI 同步。

### 5.3 状态矩阵

今后的视觉审计不能只测一个静态页面，而应覆盖：

- 0 个分析模块：主实验优先；
- 1 个模块：主对象与单一结果大尺寸比较；
- 2 个模块：三视图同屏因果闭环；
- 3–4 个模块：总览模式，并明确可能需要聚焦某一模块；
- 左右抽屉打开、关闭和固定；
- 标准桌面、用户实际反馈视口和窄屏；
- 浏览器缩放或等效 CSS 视口变化。

## 6. 全项目新原则

以后不能只问“组件是否存在”和“列宽是否足够”，必须问：

> 用户执行关键动作时，动作对象、直接原因和所选结果能否在同一个视觉瞬间被看见、比较和归因？

任何模型的旗舰交互都必须先定义它的“同屏因果集合”，再建立自动浏览器任务测试。
