# v0.10 可组合的同步实验工作台

日期：2026-08-04

## 1. 发现的逻辑缺陷

v0.8–v0.9 的薄膜旗舰已经让装置、几何、相位、相量、光谱、相图和反演共享同一套状态，但页面仍采用线性长文档结构：

```text
拖动主光线
→ 所有后续视图在后台改变
→ 用户当前却只能看见主图
→ 必须停止操作并向下滚动
→ 失去变化发生瞬间的比较关系
```

因此“共享状态”并不等于“可用于同步分析”。真正的协调视图必须同时满足：

1. 状态同步；
2. 时间同步；
3. 可见性同步；
4. 颜色和对象语义一致；
5. 用户可以按当前问题选择需要的表示。

## 2. 调研依据

### 2.1 直接操作必须支配主要界面

PhET 基于两百余次学生访谈的设计研究发现，用户首先尝试直接拖动物理对象；若界面不直觉，注意力会从物理问题转向软件操作。研究建议让可操作的实验区占据主要屏幕，并将全局控制放在清楚的小组中。

- https://phet.colorado.edu/publications/archive/Phet%20Interview%20Paper.htm
- https://phet.colorado.edu/publications/archive/PhET%20Interview%20Paper%20Part%20II.htm

### 2.2 多视图只有在协调时才产生分析价值

Multiple Coordinated Views 研究指出，多种表示能让用户从不同角度研究同一概念实体，但屏幕空间和协调机制必须被谨慎设计；无目的地同时展示大量视图会造成拥挤和认知负担。

- Wang Baldonado, Woodruff, Kuchinsky, *Guidelines for Using Multiple Views in Information Visualization*, DOI: 10.1145/345513.345271
- Boukhelifa, Roberts, Rodgers, *A Coordination Model for Exploratory Multi-View Visualization*, DOI: 10.1109/CMV.2003.1215005
- Sadana & Stasko, *Designing Multiple Coordinated Visualizations for Tablets*, DOI: 10.1111/cgf.12902
- Tan et al., *An Empirical Guide for Visualization Consistency in Multiple Coordinated Views*, DOI: 10.1109/PacificVis56936.2023.00011

### 2.3 概览、筛选、按需细节

Shneiderman 的视觉信息获取原则提出：先保留整体概览，再筛选当前关心的内容，最后按需查看细节。对于本项目，主光路就是概览，分析模块勾选就是筛选，放大窗口和目的说明属于按需细节。

- Shneiderman, *The Eyes Have It*, DOI: 10.1109/VL.1996.545307

### 2.4 开关必须语义明确

W3C WAI 的 Checkbox 与 Disclosure 模式要求：一组二元显示选项应使用有标签的复选框；隐藏与显示的状态必须可由键盘和辅助技术理解。

- https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/
- https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/

## 3. 最终结构

最终不采用以下两种极端：

### 否决方案 A：所有板块永久同时显示

问题：

- 屏幕被大量图形占满；
- 主光路失去视觉主导地位；
- 小图过小，重新产生可读性问题；
- 隐藏不相关表示的能力消失；
- Canvas 持续重绘造成不必要的性能开销。

### 否决方案 B：单一标签页一次只显示一个结果

问题：

- 无法同时比较相量和光谱；
- 切换标签会打断拖动—观察闭环；
- 用户看不到不同表征在同一状态下的对应关系。

### 采用方案：可组合的同步实验工作台

```text
主实验台（始终可见）
├── 主光路、波前和拖动把手
├── 必要实时物理量
├── 理想/现实模式与时间控制
└── 统一参数控制

同步分析模块（默认隐藏，按需勾选）
├── 真实实验装置
├── 界面反射相位
├── 多束相量
├── 光谱、能量与颜色
├── 膜厚—角度相图
├── 盲样测量与反演
├── 公式—对象映射
└── 自洽性与模型边界
```

## 4. 为什么最多同时开启四个模块

理论上可以无限勾选，但“同时可见”是有限屏幕资源。若允许八个窗口全部显示，会重新退化成小字号仪表盘。

因此采用：

- 默认 0 个；
- 推荐 1–2 个；
- 最大 4 个；
- 超过时必须先关闭一个；
- 任一窗口可进入放大模式；
- 提供问题导向的预设组合。

这不是功能限制，而是保证每个协调视图仍具有可读面积。

## 5. 预设组合

### 相位机制

- 界面反射相位；
- 多束相量。

用于回答：入射角或膜厚改变时，相位来自哪里，复振幅怎样改变？

### 光谱分析

- 光谱、能量与颜色；
- 膜厚—角度相图。

用于回答：局部工作点怎样嵌入整个参数空间，峰谷怎样移动？

### 实验反演

- 真实实验装置；
- 盲样测量与反演；
- 自洽性与边界。

用于回答：真实仪器测什么，怎样由数据反推膜厚，结果何时可信？

### 四窗全景

- 界面反射相位；
- 多束相量；
- 光谱；
- 验证。

用于演示完整的机制—观测—验证链。

## 6. 同步协议

所有模块必须读取同一状态对象：

```text
n₁, n₂, n₃
θ₁, d, λ
偏振、光源
理想/现实模式
时间相位
现实误差参数
```

任何直接拖动或参数改变都必须：

1. 先更新唯一状态；
2. 合并到一个刷新周期；
3. 重绘主实验台；
4. 重绘当前已挂载模块；
5. 更新同步状态指示；
6. 不改变未选择模块的显示状态。

不同视图不得维护各自独立的角度、膜厚或波长副本。

## 7. 响应式布局

### 超宽屏

```text
模块选择坞 | 主实验台 | 同步分析区 | 参数栏
```

主实验台和分析区同时可见。

### 中等宽屏

模块选择坞变成横向工具区，主体仍尽量保持：

```text
主实验台 | 同步分析区 | 参数栏
```

### 普通笔记本

主实验台与参数栏优先，分析区置于下一行；仍保持选择式模块，而不是恢复全部长文档。

### 手机

全部单列；同时开启模块仍受四个上限约束，并建议一次只开一个。

## 8. 模块合同

以后所有模型的可挂载分析模块必须声明：

```text
id
label
group
summary
stateInputs
observableOutputs
coordinationLinks
computationalCost
modelBoundary
```

并通过以下检查：

- 勾选和关闭不改变物理状态；
- 主实验台和已选模块在同一次操作中更新；
- 模块关闭后不留下浮动事件或动画；
- 同一物理量在所有视图使用一致颜色和符号；
- 最多四个窗口时仍可阅读；
- 放大和还原不改变参数；
- 键盘可以勾选、关闭和切换预设；
- Canvas 在挂载后按实际尺寸重新高清绘制。

## 9. 全项目迁移规则

此结构不是薄膜专属。后续模型按以下方式迁移：

1. 为每个模型确定不可隐藏的“主实验台”；
2. 只保留直接操作所必需的几何、状态和控制；
3. 将机制、结果、全局参数空间、实验测量和验证拆成可挂载模块；
4. 按问题提供 2–4 个预设组合；
5. 不允许为了统一而机械地给简单模型制作八个模块；
6. 模块数量由物理问题决定，而不是由页面模板决定；
7. 所有模块共享状态，但只挂载当前任务需要的表示。

统一逻辑为：

```text
保持一个稳定的可操作物理对象
→ 用户声明当前想分析的问题
→ 系统挂载最相关的协调表示
→ 用户连续操控
→ 多视图在同一时刻共同响应
→ 比较、归因和验证在视野内完成
```
