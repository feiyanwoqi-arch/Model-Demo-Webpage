# v0.11 自适应可见性策略：什么必须常驻，什么应在边缘唤出

日期：2026-08-04

## 1. 问题不是“侧栏要不要隐藏”，而是信息是否参与当前闭环

薄膜工作台的界面元素不能按左右位置分类，而应按它在当前任务中的功能分类：

```text
用户正在操控什么？
→ 操控造成的关键结果是否必须立即看见？
→ 该控件是否高频使用？
→ 隐藏后能否被轻易发现和恢复？
→ 展开时是否会遮挡正在比较的对象？
```

由此建立四级可见性：

1. 常驻核心；
2. 边缘轨道；
3. 按需展开；
4. 模态或独占流程。

## 2. 调研结论

### 2.1 永久显示与可关闭侧栏应由使用频率和内容优先级决定

Material Design 将桌面侧栏区分为永久、可关闭和模态：频繁切换且屏幕足够大时可永久显示；内容优先、侧栏使用较少时应使用可关闭抽屉；移动端应使用模态抽屉。

- https://m2.material.io/components/navigation-drawer
- https://developer.android.com/develop/ui/compose/components/drawer

### 2.2 自适应界面应在 minimal、compact 和 expanded 之间切换

Microsoft NavigationView 的 Auto 模式会随窗口宽度在最小、紧凑和完整显示之间切换；紧凑模式保留一条可发现的窄轨，而不是让功能完全消失。

- https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/navigationview
- https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.controls.navigationviewdisplaymode

### 2.3 桌面侧栏应该允许用户显式显示、隐藏或固定

Apple 的侧栏指南建议在桌面提供显示/隐藏控制，并根据窗口尺寸自动折叠；同时强调用户应能个性化工作区，而不是让系统一直猜测意图。

- https://developer.apple.com/design/human-interface-guidelines/sidebars
- https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/

### 2.4 纯 hover 自动消失存在严重问题

WCAG 2.1 的“悬停或聚焦内容”要求悬停内容必须：

- 可关闭；
- 鼠标可以移动到内容上而不消失；
- 在用户移走、显式关闭或内容失效前保持可见。

因此不能使用“鼠标离开触发边缘一瞬间就关闭”的实现。

- https://www.w3.org/WAI/WCAG21/Understanding/content-on-hover-or-focus.html
- https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/

### 2.5 隐藏界面不是越多越好

Nielsen Norman Group 对 Zen Mode 的分析指出，自动隐藏工具栏可能释放空间，但系统很难可靠判断用户意图；覆盖目标内容、反复播放动画或隐藏关键操作会降低可用性。隐藏必须服务于任务，而不是只追求视觉空旷。

- https://www.nngroup.com/articles/zen-mode/
- https://www.nngroup.com/articles/animation-usability/

## 3. 薄膜工作台的最终定性

| 界面部分 | 性质 | 显示策略 | 理由 |
|---|---|---|---|
| 主光路、波前、拖动把手 | 物理对象本体 | 永久常驻 | 所有分析都由它驱动，隐藏即失去实验对象 |
| 已选同步分析窗口 | 当前任务的观测量 | 永久常驻，直到用户关闭 | 用户选择它们就是为了拖动时同步比较 |
| 核心实时判据 | 即时反馈 | 常驻但紧凑 | 角度、膜厚、当前状态必须无需寻找即可确认 |
| 模式、时间控制 | 全局状态 | 常驻紧凑工具条 | 影响所有视图，状态改变必须始终可见 |
| 左侧模块选择 | 次级配置 | 窄轨常驻，抽屉按需展开 | 选完模块后不参与连续观察，但必须容易再次发现 |
| 右侧完整参数检查器 | 间歇性控制 | 窄轨常驻，抽屉按需展开 | 直接拖动是主交互；折射率、光源等参数只在需要时调整 |
| 板块目的、作用、建议操作 | 解释文本 | 点击式 disclosure | 阅读需要稳定停留，不适合 hover 消失 |
| 公式细节、模型边界 | 深层解释 | 可挂载模块或 disclosure | 并非每次拖动都需要，但必须可验证和可恢复 |
| 盲样生成、揭示真值 | 独立实验流程 | 挂载模块；必要时局部确认 | 它是任务流程，不应占用主界面常驻面积 |
| 手机端左右侧栏 | 触摸界面 | 显式按钮打开的模态抽屉 | 触摸没有 hover，边缘手势也可能与浏览器冲突 |

## 4. v0.11 采用的交互模式

### 4.1 窄轨始终可见

左右边缘各保留一个窄轨：

- 左侧显示“模块”和当前选择数量；
- 右侧显示“参数”和核心参数符号；
- 窄轨本身不明显压缩中央实验区域；
- 用户不会因为抽屉收起而失去功能发现性。

### 4.2 展开条件

细指针桌面设备：

- 悬停 140 ms 后打开；
- 键盘聚焦立即打开；
- 点击窄轨切换；
- 鼠标可以移动进抽屉内部；
- 离开 560 ms 后才收起；
- 操作滑块期间禁止自动收起。

触屏和小屏：

- 不使用 hover；
- 点击底部按钮打开；
- 使用遮罩；
- 点击遮罩或关闭按钮收起。

### 4.3 固定功能

每个抽屉有图钉：

- 固定后持续显示；
- 宽屏为固定抽屉预留空间；
- 较窄屏幕即使固定也保持覆盖式，防止主实验台被压得过窄；
- 固定状态保存在 localStorage；
- Escape 可解除固定并关闭。

### 4.4 为什么有延迟

立即打开会被经过屏幕边缘的偶然鼠标轨迹反复触发；立即关闭则会在用户从窄轨移入抽屉时造成闪退。

因此采用：

```text
打开延迟 140 ms
关闭延迟 560 ms
```

这两个值不是物理常数，后续应通过实际使用继续调整。

## 5. 主界面重新分配

抽屉收起时，主要宽度只分给：

```text
主实验台 | 同步分析区
```

顶部标题区压缩为紧凑标题和公式摘要；长目的说明折叠成点击式说明。完整参数和模块列表覆盖展开，不再永久占据四分之一到三分之一屏幕。

## 6. 全项目的判定算法

以后任何模型新增一个界面块，按以下顺序判断：

### A. 它是否是当前直接操控对象？

是：常驻。

### B. 它是否是用户主动选择来和主对象同步比较的结果？

是：选择后常驻，未选择时不挂载。

### C. 它是否改变全局状态，而且在连续操作中高频使用？

是：常驻紧凑控制。

### D. 它是否只用于偶尔配置、筛选或切换？

是：边缘轨道或可关闭抽屉。

### E. 它是否是需要稳定阅读的说明？

是：点击式 disclosure，不使用 hover。

### F. 它是否会阻断主任务或需要用户明确完成一个步骤？

是：模态或独占流程，但必须谨慎使用。

## 7. 禁止事项

1. 禁止把关键操作只藏在 hover 中；
2. 禁止没有可见触发器的隐形边缘热区；
3. 禁止鼠标从触发器移向抽屉时抽屉消失；
4. 禁止滑动参数时抽屉自动关闭；
5. 禁止触屏设备依赖 hover；
6. 禁止自动隐藏用户正在比较的分析窗口；
7. 禁止展开抽屉后永久压缩主图，除非用户主动固定；
8. 禁止为了动画感反复移动外围 UI；
9. 禁止把长解释放在悬停提示中；
10. 禁止由系统自动决定哪些已选分析模块应该关闭。

## 8. 验收标准

### 自动检查

- 脚本加载顺序；
- hover 仅对 fine pointer 启用；
- `aria-expanded`、`aria-pressed`；
- Escape 关闭；
- 固定状态持久化；
- 滑块拖动期间保持打开；
- 响应式触摸模式；
- 主实验台与同步分析区的最小宽度。

### 浏览器视觉检查

- 2560×1440：中央两区必须同时舒展显示；
- 1920×1080：抽屉收起后不得浪费左右空间；
- 展开左抽屉：不能遮住全部主光路；
- 展开右抽屉：滑块可操作，移入抽屉不消失；
- 抽屉收起：边缘窄轨仍明显可发现；
- 手机：只通过点击打开，并出现遮罩；
- 缩放与窗口改变后 Canvas 必须重新高清绘制。
