# 交互式物理模型核心标准 v1.3：可读性与完整呈现

版本日期：2026-08-05

## 触发原因

R2 v0.15 在自动验收和人工缩略图检查中被判为通过，但用户在真实浏览器中发现：

- Canvas 内标签字号过小，正常观看距离下无法轻松阅读；
- 两个分析模块被压缩在右侧，空间分配优先了“同屏”，牺牲了信息尺度；
- 下方模块与 Canvas 底部文字没有完整显示。

这说明此前验收仍把“元素存在、没有明显溢出、整体截图看起来完整”误当成了“真正可读”。

## 根因

1. DOM 字号检查没有覆盖 Canvas 内文字；
2. 验收只检查 Canvas 外框和宽高比，没有检查内部文字的实际显示像素；
3. 必需模块可见比例阈值错误地设为 90%，等价于允许 10% 内容被视口裁掉；
4. 人工检查以整张缩略图为主，没有在 100% 像素尺度逐个阅读标签；
5. “主实验台与两个模块同屏”被当成硬目标，压过了最低可读尺度；
6. 公网验收验证了资源、交互和宽度利用率，却没有验证模块完整性与文字可读性。

## 新增强制标准

### 1. 可见不等于可读

任何文字都必须在正常观看距离下无需放大即可阅读。不得以“像素中存在文字”“截图放大后能辨认”作为通过依据。

### 2. Canvas 有效字号

Canvas 文字的有效显示字号定义为：

```text
有效字号 = 逻辑字号 × min(CSS显示宽/逻辑宽, CSS显示高/逻辑高)
```

桌面端最低标准：

- 核心结论、状态、判据：有效字号 ≥ 18 px；
- 物理对象与关键路径标签：有效字号 ≥ 16 px；
- 次级解释与图例：有效字号 ≥ 14 px；
- 不允许出现低于 14 px 的教学文字。

### 3. 字形完整与安全边距

Canvas 中每个文字包围盒必须完整位于绘图区，并与四周保持安全边距：

```text
安全边距 ≥ max(12 px, 0.75 × 有效字号)
```

“只露出一部分”“贴着边缘但尚未完全消失”均判定失败。

### 4. 必需模块必须 100% 呈现

需要当前任务阅读的卡片、Canvas、标题、图例和结论必须完整进入当前检查视口：

- 可见比例必须为 1.000；
- 底边与视口至少保留 16 px 安全距离；
- 不再接受 90%、95% 等部分可见阈值。

若页面采用纵向流程，验收应分别滚动到每个模块并检查其完整状态，而不是强迫所有内容挤在同一个首屏。

### 5. 同屏目标服从可读性预算

“同时看到多个表示”是手段，不是最高原则。当同屏会使任一关键文字低于最低有效字号时，必须改用：

- 主实验台全宽；
- 分析模块置于下方；
- 宽屏双列、窄屏单列；
- 通过自然滚动完成机制—判据的连续阅读。

禁止为了同屏而缩小字体、压扁 Canvas 或裁掉模块底部。

### 6. 人工验收必须按 100% 像素阅读

每张关键截图必须：

1. 以原始像素 100% 打开；
2. 逐一读出主图、两个分析模块和抽屉中的关键文字；
3. 检查最上、最下、最左、最右文字；
4. 记录无法一眼读出的标签；
5. 不允许只看整体构图或缩略图。

### 7. 用户画面拥有最高纠偏权

用户真实浏览器画面发现的问题，优先级高于实验室截图和自动指标。发生冲突时：

```text
用户真实画面
> 公网原尺寸截图
> 本地原尺寸截图
> 自动几何指标
> 代码意图
```

### 8. 公网验收扩展

GitHub Pages 验收除资源、交互、溢出外，必须新增：

- Canvas 最小有效字号；
- 主实验台与每个模块的完整呈现；
- 底部字形安全边距；
- 100% 原图人工阅读记录；
- 用户实际报告视口的专项截图。

## R2 v0.16 的直接要求

- 主实验台改为全宽，不再与两个模块挤成左右窄列；
- 两个分析模块移到主实验台下方；
- 宽屏双列，空间不足时自动单列；
- 所有 Canvas 教学文字有效字号不得低于 14 px；
- 所有核心标签有效字号不得低于 16 px；
- 删除或合并冗余小字，不能单纯无限放大；
- 模块底部文字与边界必须完整显示；
- 五种桌面视口和公网 1735×865 均重新验收；
- v0.15 的通过结论撤销，只有 v0.16 新验收和公网复验完成后才能重新宣告通过。
