# R2 平面镜虚像：真实运行与视觉验收（v0.15）

## 目标

本轮只处理 R2「平面镜虚像」。依据 v1.1 主标准和 v1.2 增补，先建立当前版本的真实浏览器基线，再根据截图与任务结果返工，不从 R1 的修复机械复制界面。

## R2 的统一底层模型

R2 的本质不是“画一个对称箭头”，而是一条完整的信息链：

```text
物体每个点发出发散光
→ 有限镜面截获其中一部分
→ 镜面按局部反射定律改变方向
→ 只有进入瞳孔的光参与当前观察
→ 视觉系统按到达方向反向追迹
→ 多条反向延长线交于镜面对称点
→ 眼睛/相机可记录虚像，但镜后屏幕接不到真实会聚光
```

因此主实验台必须让用户同时辨认：物体、有限镜面、眼睛、真实入射光、真实反射光、反向延长线、虚像和必要反射点。

## 必须完成的学习任务

1. 拖动物体，确认物距、物高与虚像同步变化，且物像关于镜面对称；
2. 拖动眼睛，确认真实反射路径与有限镜面的必要命中点变化，但虚像位置不因观察者改变；
3. 直接拖动镜面端点，使物体顶部或底部必要光线被截断；
4. 恢复足够镜面覆盖范围，确认完整物体重新可见；
5. 区分镜前实线、镜后虚线和镜后屏幕判据；
6. 在五个桌面视口中检查默认态、拖动态、有限镜面失败态和抽屉开启态。

## 物理验收条件

- 像距大小始终等于物距；
- 像高始终等于物高，放大率为 +1；
- 眼睛移动不改变虚像几何位置；
- 进入眼睛的每条反射光与对应反向延长线共线；
- 有限镜面完整可见判据由顶部和底部两条必要光线共同决定；
- 判据必须比较“必要反射点区间是否被有效镜面区间包含”，不能只比较两个长度；
- 镜后屏幕不能在虚像点接收到真实会聚光。

## 视觉验收条件

以下任一情况均视为失败：

- 真实光线和反向延长线颜色或线型难以区分；
- 物体、虚像、眼睛或镜面被缩小到难以定位；
- 镜面有效区和非有效区无法区分；
- 必要反射点标签碰撞、贴边或被裁切；
- 主实验台大面积空白，而关键光路集中成小团；
- 宽屏仍被旧版 1540px 容器限制；
- 两个分析模块 Canvas 比例失真；
- 抽屉或边缘按钮遮挡关键光路；
- 高屏幕抽屉被无意义地强制撑满，内容下方出现大片空白；
- 用户无法一眼回答“光实际走到哪里”和“为什么像看起来在镜后”。

## 目标视口

- 2560 × 1440
- 1920 × 1080
- 1735 × 865
- 1440 × 900
- 1366 × 768

## 基线验收发现

严格基线并未把旧版测试通过视为完成，真实运行暴露出：

1. **宽屏被旧版版心限制**：2560×1440 的任务区只使用约 60.2% 视口宽度，1920×1080 只使用约 80.2%；
2. **主实验台物理对象集中成小团**：有限镜面、物体、眼睛、虚像与必要反射点之间缺乏清晰层级；
3. **分析 Canvas 被布局拉伸**：局部机制图和可见性图的设计比例没有保持；
4. **“状态同步”仍不完整**：物体移动后，眼睛反向追迹模块没有读取更新后的物距、物高和眼睛状态；
5. **有限镜面判据不够直观**：只给出“当前镜高”和“所需镜高”，没有明确比较两个空间区间；
6. **直接操作不足**：镜面只能通过参数滑块改变，主实验台上的镜面端点不是可验证控制对象；
7. **初始渲染存在竞态**：1366×768 下，Canvas 在布局稳定过程中被晚到的尺寸重设清空，第一次操作前主图可能空白；
8. **抽屉定位和高度不合理**：左抽屉一度被父级内边距推向视口外；高屏幕下两侧抽屉强制占满全高，留下大片空白；
9. **底部说明贴边**：分析模块最底部两行文字在低高度视口中存在截断风险。

## 实施修复

### 主实验台

- 明确分出“真实传播区（镜前）”和“虚拟定位区（镜后没有真实光）”；
- 同时绘制物体、对称虚像、有限镜面有效区、非有效区、眼睛、顶部/底部必要反射点；
- 实线表示真实入射与反射光，虚线表示观察者沿到达方向的反向追迹；
- 必要点落在镜面之外时，用减弱的候选路径和红色叉号表示“本应命中但镜面不存在”；
- 常驻显示物距、像距和有限镜面完整可见判据；
- 镜面上下端点成为可直接拖动对象。

### 同步分析区

- “眼睛的反向追迹”改为有限瞳孔接收两条真实光，并显示两条反向延长线交于同一虚像点；
- “有限镜面与完整可见性”直接比较：
  - 顶部必要点；
  - 底部必要点；
  - 所需区间；
  - 当前有效镜面区间；
  - 区间包含判据；
- “装置与观察”区分眼睛/相机可记录虚像与镜后屏幕不能接收真实会聚光；
- 所有模块读取统一状态，物体、眼睛、镜面变化后同步重绘。

### 布局与运行稳定性

- 只对 R2 解除旧版 `1540px` 的 `#view` 限制；
- 五个桌面视口中保持主实验台与两个分析模块同屏；
- 分析 Canvas 固定保持 `720∶260` 设计比例；
- 修复左右抽屉的真实视口定位；
- 高屏幕抽屉改为内容自适应高度，超出视口时再滚动；
- 增加 ResizeObserver、稳定帧和延时重绘，防止 Canvas 在布局稳定后变空；
- 将底部说明移入安全区域。

## 最终自动验收

### 五视口任务审计

每个目标视口执行：

1. 加载并等待布局与 Canvas 稳定；
2. 检查主图非空、任务区可见比例、横向溢出、字体、按钮与 Canvas 比例；
3. 真实拖动物体顶部：
   - 物距 `270 px → 320 px`；
   - 物高 `150 px → 195 px`；
4. 真实拖动眼睛：
   - 眼睛高度 `430 px → 270 px`；
   - 物距和物高保持不变；
5. 通过参数抽屉将镜面高度设为 `80 px`，确认部分截断；
6. 将镜面高度设为 `500 px`，确认完整可见；
7. 打开模块抽屉，检查完整可见与无裁切；
8. 再次读取最终布局指标。

结果：

- 2560×1440 任务区宽度利用率：`93.75%`；
- 1920×1080 任务区宽度利用率：`94.00%`；
- 五视口主 Canvas 初始非空检测全部通过；
- 左右抽屉可见比例均为 `1.000`；
- 浏览器错误：`0`；
- 严格断言失败：`0`。

### 直接控制审计

在 1735×865 与 1366×768 中直接拖动镜面上端点：

- `260 px → 90 px`：部分截断；
- `90 px → 500 px`：完整可见；
- 两个视口错误与断言均为 `0`。

### 高屏幕抽屉审计

- 2560×1440：
  - 参数抽屉约 `670.5 px` 高；
  - 模块抽屉约 `685.9 px` 高；
- 1920×1080：
  - 参数抽屉约 `670.5 px` 高；
  - 模块抽屉约 `685.9 px` 高；
- 均完整位于视口内，内容高度与抽屉高度一致，不再出现全高空白。

## 人工视觉复验

逐张检查以下证据：

- 五视口默认态；
- 物体拖动态；
- 眼睛拖动态；
- 短镜面与参数抽屉；
- 完整可见态；
- 模块抽屉；
- 两视口镜面端点直接拖动的短镜/长镜状态；
- 两个高屏幕的左右内容自适应抽屉。

人工复验确认：

- 1366×768 默认主 Canvas 不再空白；
- 真实光、反射光与反向延长线可区分；
- 顶部/底部必要点、镜面有效区和所需区间可读；
- 默认“当前镜高大于所需区间长度却仍部分截断”的表面矛盾，已通过区间位置对比解释清楚；
- 分析模块底部说明不再截断；
- 左右抽屉无裁切，高屏幕下无大片无意义空白；
- 五视口未再发现明显标签碰撞、比例失真或宽屏版心浪费。
